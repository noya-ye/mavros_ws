# 第二轮 C++ 资源优化与急停修复

> 第二轮历史说明。本轮急停修复继续保留；当前第三轮资源优化及等价验证见 [OPTIMIZATION_V3.md](OPTIMIZATION_V3.md)。

本轮在第一轮版本上继续减少地图、样条计算和消息构造开销，并修复急停后轨迹服务器继续执行旧轨迹的问题。默认参数保持 10×10 m、0.05 m 分辨率、世界高度 0.1～2.0 m、0.45 m 障碍膨胀。没有估计假树中心，也没有增加虚拟圆形障碍。原始源码保留在 `C:/SSH/ego_2d_planner_pkg/`，本交付是独立副本。

## 资源改动

1. 将原来的膨胀圆盘按行预计算为连续区间，使用连续内存填充。格点判定仍使用原公式，半径和障碍范围不变。
2. 每帧观测的世界格用复用数组排序去重，保持同一世界格每帧只计一次观测。候选确认时间、次数及丢失容忍规则不变。
3. 已确认障碍按 16×16 个世界格分块，每块用 32 字节位图存格状态；另有哈希表及分配器开销。局部地图只遍历与其相交的块，避免每帧遍历全部历史障碍。仍保留全部历史，不自动删除障碍。
4. 优化器复用第一次代价和梯度计算，规划重试复用控制点及参考点容量，避免重复计算和不必要的路径复制。
5. 地图、路径、标记和二维点云仅在有订阅者时构造，复用消息容量。选定路径仅在路径改变后更新几何数据，发布时刷新全部时间戳；后加入的订阅者仍能在下一次发布收到当前路径。FSM 缓存活动样条和同一次采样结果，保持原有限差分公式。

第一轮的双扫描距离场、A* 工作空间复用、PointCloud2 输入验证、二维点云输出和 XML 启动配置均保留。所有节点和新增测试程序为 C++，Shell 文件仅编排编译和运行。

## 急停链路

新增消息 `EmergencyStop2D`，话题 `/ego_2d_planner/emergency_stop`，可靠、非持久化、队列深度 1。原 `Bspline2D` 消息格式不变。

- FSM 进入 `EMERGENCY_STOP` 时，捕获当时里程计 xyz 作为固定保持点，清除活动轨迹和选定路径，立即发送停止消息。
- 后续每次 FSM 定时回调重发相同的停止时间戳和保持点，覆盖重试规划期间；直到真正发布新的 Bspline 后才停止重发。停止条件是已发布新轨迹，并非收到服务器确认。
- 服务器收到有效停止消息后撤销旧控制点，立即输出保持指令，并按原配置 50 Hz 持续输出固定位置、零速度、零加速度、零偏航角速度，保持当时的偏航角。
- 使用消息 `header.stamp` 的发行时间排序。旧于或等于停止时间戳的轨迹不能解除保持；只有严格更新且校验有效的轨迹才恢复运动。重复停止消息不移动保持点，晚到且早于新轨迹的停止消息不会撤销该新轨迹。
- 新轨迹先在临时缓冲区验证，再替换活动轨迹。错误坐标系、异常时间、非有限参数或控制点不会清掉当前有效轨迹或保持状态。
- `hover_if_plan_failed=false` 仍会撤销服务器中的旧轨迹，该参数只影响旧 `local_goal` 输出。

必须同时更新 FSM、轨迹服务器和消息定义，再重新编译并重启两个节点。只替换规划器不能修复旧服务器。

## 编译与部署

将本包放入 ROS 2 Humble 工作空间 `src/`，沿用已有 `quadrotor_msgs` 依赖：

```bash
source /opt/ros/humble/setup.bash
cd ~/ros2_ws
colcon build --packages-up-to ego_2d_planner_pkg --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
ros2 launch ego_2d_planner_pkg ego_2d_planner.launch.xml
```

默认配置的固定坐标系为所给 bag 的 `lidar`，点云 `/cloud_registered_filtered`，里程计 `/fastlio2/lio_odom`，目标 `/simple_2d_planner/goal`。实际部署需确保这些输入确实在同一固定坐标系中；没有自动 TF 转换。

每个版本必须加载其自己的安装目录及动态库，不能在新版环境中直接运行旧版可执行文件。当前核心类布局已改变，混用动态库会造成异常。对照回放脚本现在分别加载对应环境，并记录、核验 `ldd` 的核心库路径。

## 测试范围

详细数字和原始证据见配套验证包的 `analysis/v2/RESULTS.md`。测试环境是 WSL Ubuntu 22.04、ROS 2 Humble、x86-64；不是 Jetson Orin NX。

- 完整 bag 1065 帧的确定性核心比较：42,600,000 个距离值及所检查的占用、路径、控制点和时长均无数值差异。93 次独立规划两版同为 72 次成功、21 次失败。
- 地图/A* 回归：10 种配置、180 帧、4320 次搜索通过；大缓存压力测试：1956 帧、99,014 个永久格、480 帧重访，逐帧语义摘要与第一轮版本一致。
- 优化器及管理器：66 个用例、20,967 个字段通过，其中 17,068 个浮点值逐位相同。
- ROS 点云投影：两种高度基准、空点云、异常字段和恢复，共 38 次断言通过。
- ROS 急停：39 次断言通过，涉及 32 个不同检查名称，覆盖取消旧轨迹、持续保持、乱序及无效消息、新轨迹恢复、`hover=false` 的 FSM→服务器链路，以及路径缓存更新。旧服务器在撤销旧轨迹的负对照检查中失败。

核心比较从相同观测重新规划，不把 bag 中飞过的路线当作最优路线；它不包含闭环控制。ROS 性能回放使用可视化话题订阅器，但没有运行 RViz 渲染。

## 仍然存在的限制

1. 急停修复保证命令层撤销和位置保持，没有新增受加速度约束的制动轨迹，不能据此确定实际制动距离；已经发往下游队列的旧指令无法收回。原来的规划失败阈值和急停触发时机未改变。
2. 停止和恢复依赖共同、单调的 ROS 时钟。`/clock` 回退、循环播放或切换时间基准前，应停止回放并同时重启两个节点；本版没有时间回退自动恢复逻辑。
3. 速度/加速度仍主要通过软惩罚处理，重规划与执行起点时间仍可能偏离；没有证明严格限幅或指令连续。碰撞检测仍为离散采样，没有连续扫掠保证。
4. 永久障碍保持原有不清除策略。误检、定位漂移和不断扩大的探索范围仍会使缓存增长；分块和位图降低开销，不等于无限时长下内存恒定。静态场景假设没有解决传感器漏检。
5. 8×8 m、小高度层仍只是可选试验配置，会改变可见障碍和搜索边界。本轮默认不缩小感知范围，不据此宣称严格等价或实机安全。

本轮结束后不自动开始下一轮优化；实机 CPU、长期内存和闭环飞行尚未验证。
