# 第三轮 C++ 资源优化

本轮以第二轮版本为对照，只修改距离场计算和轨迹服务器中的重复计算。目标是在保持现有规划行为的前提下降低 CPU 开销，没有新增大数组或历史缓存。第二轮的急停撤销修复继续保留。

## 保持的输入与行为

- 默认局部地图仍为 10×10 m、5 cm 分辨率，点云高度范围仍为世界坐标 z=0.1～2.0 m。
- 障碍仍按原有点云占用方式处理，膨胀半径仍为 45 cm。没有估计假树中心，没有新增虚拟树体圆，也没有通过删除稀疏点降低负载。
- 点云、里程计和目标话题，世界格确认与永久障碍规则，A* 搜索、B 样条优化参数及重试条件均沿用第二轮。
- FSM 触发条件、碰撞检查步长、轨迹采样时刻、速度和加速度计算公式、偏航处理以及配置的发布频率均不变。
- 不把 bag 中录制的飞行路线当作最优路线。确定性测试使用相同观测、起点和目标分别重新规划。

本轮生产代码的改动范围仅为 `src/plan_env/grid_map_2d.cpp` 和 `src/plan_manage/traj_server_2d_node.cpp`。默认参数和消息定义没有变化。

## 两处资源优化

### 距离场：内部格直接访问，边界格保留原检查

仍先独立初始化距离数组：占用格为 0，其余为原来的大距离值，然后按原顺序执行前向和反向两遍扫描。

每遍扫描对具有全部所需邻居的内部格直接访问当前行与相邻行，避免为每个邻居重复计算坐标、线性索引和边界判断。首末行、左右边界以及窄地图继续使用原来的带边界检查逻辑。

八邻域的访问顺序、水平和对角距离权重、严格小于比较、占用格跳过规则均保留；使用现有距离数组完成计算，不增加另一份地图。保留独立初始化的实现便于逐项核验计算顺序。

### 轨迹服务器：同一时刻共用样条位置参数

原实现分别计算位置、速度和加速度时，会重复执行时间限幅、段号计算和局部参数计算。现在同一指令时刻只计算一次 `SplineLocation`，包含段号、局部参数 `u` 和 `u²`，三种求值共用这些结果。

各自的基函数公式及运算顺序不变。尚未开始的轨迹仍保持起点；结束后的保持与非保持分支仍按原配置执行；偏航前视仍在其原来的时间点求值。控制点数量检查和互斥锁范围保留，局部参数不会跨轨迹更新缓存。

这两项都减少既有计算中的重复工作。没有调整轨迹、限速策略、坐标系或回放时序，也没有新增多线程、GPU 路径或长期数据结构。

## 等价验证与性能证据

详细性能结果、测试环境、统计口径及原始文件见配套验证包的 [analysis/v3/RESULTS.md](../../analysis/v3/RESULTS.md)。该报告区分核心函数、ROS 进程和订阅负载；本说明不以核心函数耗时推算实机进程 CPU。

已完成的确定性比较包括：

- 完整 bag 的 1065 帧核心对照。42,600,000 个距离值，以及所检查的占用、地图几何、A* 路径、选定路径、控制点、轨迹时长、结点间隔、迭代次数和代价均无数值差异。比较双方使用相同输入和有效配置。
- 地图/A* 回归、距离场 oracle 及历史缓存压力对照。测试覆盖地图边界、不同地图配置及既有永久障碍行为，具体数量和结果列于配套报告。
- 轨迹服务器直接编译第二轮快照与本轮生产源码进行比较，没有另写一份简化求值器代替生产实现。294 组轨迹、29,106 个求值样本、29,121 次指令检查、902,847 次浮点逐位检查通过。

服务器测试覆盖最少控制点、不同结点间隔、结点两侧的相邻浮点时间、消息时长短于或长于自然时长、零时长回退、未来起点、结束保持、偏航边界、短控制点保护和急停保持。它验证所测输入上的一致性，不代表所有平台、所有浮点输入的形式化证明。

第二轮急停链路的 39 次断言和点云投影的 38 次断言也已通过。完整 ROS 回放与资源统计见配套报告。订阅器接收间隔不是内部计算耗时，也不是硬实时保证；ROS 回放中的定时回调依赖调度，不以两次回放逐消息相同作为核心等价的替代证据。

本轮未引入减少历史数据量的策略，因此不承诺进程内存下降。WSL/x86-64 结果不能直接换算为 Jetson Orin NX 8GB 上的 CPU 百分比，也不能据此承诺原来的 80% 峰值降到某个数值。

## 保留的急停修复与限制

第二轮的 `/ego_2d_planner/emergency_stop` 链路仍在使用：FSM 进入急停时记录固定保持点并发送取消消息；轨迹服务器撤销旧控制点，立即并持续发布该位置的保持指令，速度、加速度及偏航角速度为零。旧轨迹不能解除保持，只有时间戳严格更新且校验有效的新轨迹才能恢复执行。具体协议见 [OPTIMIZATION_V2.md](OPTIMIZATION_V2.md)。

仍需保留以下使用边界：

1. 急停是命令层撤销和位置保持，没有新增受动力学约束的制动轨迹；已经进入下游队列的旧指令无法收回。原来的失败阈值和急停触发时机未改变。
2. 停止与恢复依赖共同、单调的 ROS 时钟。回放时间倒退、循环播放或切换时间基准前，应同时重启规划器和轨迹服务器；没有时间回退自动恢复功能。
3. 速度和加速度仍主要通过软惩罚处理，轨迹衔接及离散碰撞检测的既有限制仍在。本轮不证明严格限幅、连续碰撞安全或实机跟踪性能。
4. 永久障碍仍按原规则保存。误检、定位漂移和不断扩大的探索范围仍可能使缓存增长，也没有新增传感器漏检恢复机制。

## 编译与部署

生产节点和新增验证程序均为 C++，启动文件为 XML；Shell 只用于编译和测试编排。将本包放入已有 ROS 2 Humble 工作空间的 `src/`，保留原有 `quadrotor_msgs` 等依赖：

```bash
source /opt/ros/humble/setup.bash
cd ~/ros2_ws
colcon build --packages-up-to ego_2d_planner_pkg --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
ros2 launch ego_2d_planner_pkg ego_2d_planner.launch.xml
```

XML 默认同时启动规划器与轨迹服务器。回放已有 bag 时使用 `use_sim_time:=true`，并由播放器提供 `/clock`；实机部署沿用真实时间配置。默认输入为 `/cloud_registered_filtered`、`/fastlio2/lio_odom`、`/simple_2d_planner/goal`，固定坐标系为所给数据使用的 `lidar`，没有新增 TF 自动转换。

规划器、轨迹服务器和其核心动态库应来自同一次构建与安装环境。对照测试时分别加载各版本的安装环境，不能混用旧可执行文件和新核心库。从尚未包含第二轮急停消息的旧版本升级时，还应重新构建消息依赖并同时重启两个节点。

可选小地图和高度层配置继续保留，但本轮没有将其设为默认，也不以它们的障碍裁剪收益解释上述资源优化。Orin 实机负载、长期运行和闭环飞行仍需要单独验证。
