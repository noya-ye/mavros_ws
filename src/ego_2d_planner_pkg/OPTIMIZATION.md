# C++ 资源优化与二维点云使用说明

> 第一轮历史报告。当前第三轮资源优化见 [OPTIMIZATION_V3.md](OPTIMIZATION_V3.md)，第二轮改动和验证见 [OPTIMIZATION_V2.md](OPTIMIZATION_V2.md)。下文性能数字对应第一轮；末尾的旧轨迹未撤销问题已在第二轮修复，其余限制仍需注意。

本版保留原有 C++ 规划流程，增加局部高度层投影配置和二维点云输出。性能等价验证使用原来的 10×10 m 地图、0.05 m 分辨率、世界坐标 z=0.1～2.0 m，不靠删除障碍点取得加速。新增处理、bag 导出、数值比较与 ROS 回放测试程序均为 C++。原 Python launch 替换为 XML 启动配置，原有 config、use_rviz、use_traj_server、rviz_config 参数保留，增加 use_sim_time。

## 原算法思路

1. 读取 FAST-LIO2 点云和里程计，按高度过滤点云，投影到以当前位置为中心的二维占用栅格。原程序本来就是二维规划，并非三维体素规划。
2. 对持续观测到的障碍建立永久缓存，加入当前地图；按 0.45 m 膨胀，计算到膨胀障碍的八邻域距离场。
3. 八邻域 A* 搜索避障引导路径，禁止对角穿过占用格角点。
4. 构造三次 B 样条控制点，优化平滑、碰撞、速度/加速度可行性和路径贴合代价；失败时提高碰撞权重并重试。
5. 对输出轨迹做采样碰撞检查，FSM 负责重新规划；轨迹服务器将 Bspline2D 转为 `/position_cmd`。

这不是全局最优轨迹算法。A* 针对当前栅格代价，后续样条是带权重的局部优化；栅格最短路径、飞行时间最短、转弯平滑和最大安全间距也不是同一个目标。

## 实际修改

- 距离场由优先队列传播改为正反两次扫描，保留原直线/对角步长及空地图距离值。这是原八邻域距离的快速计算，未改成精确欧氏距离。消除每帧大量堆操作，不需要第二份距离缓存。
- 膨胀圆盘偏移在配置时预计算，保留原判定公式，避免逐障碍格重复开方。
- A* 复用 g 值、父节点、关闭标记和堆数组；移除堆节点中未使用的 g 字段。每次搜索仍清空状态，邻居顺序和堆比较规则不变。同一 A* 实例不可并发搜索；当前节点采用串行 executor。
- 先验证 PointCloud2 布局，再重置地图。缺失/错误 XYZ、截断数据等不再先清空上一次有效地图。当前输入要求 FLOAT32 XYZ、紧密排列、小端数据，适用于所提供的 FAST-LIO2 bag。
- 增加 `grid_map/cloud_z_reference`：`world` 使用原绝对高度；`planning_height` 使用 `manager/fixed_z` 加上下偏移。没有自动估计地面，也没有跟随里程计 z 改变切片。
- 增加 `/ego_2d_planner/cloud_2d`：每个未膨胀占用格输出一个点，XY 为格中心，z 为规划高度，包含已确认的历史障碍。它是二维地图的平面表示，不保留原始点的 intensity 和具体高度；只在有订阅者时构造并发布。

## PDF 方法如何使用

参考所提供 PDF 的局部范围、高度层筛选和 XY 投影思路。PDF 中用于车辆侧壁等特征识别的离地高度阈值，不能直接当作飞行器避障范围。地面分割、Hough 直线、删除大连通域等识别步骤没有搬入规划器，以免删除需要避让的障碍。

bag 没有可直接使用的地面高度估计。机体上下尺寸、实际规划高度基准及垂直安全余量尚未确认，因此窄高度层保留为离线候选。高度层必须覆盖机体占用高度并考虑定位误差；二维规划不能同时表达“可从其下方穿过”和“必须绕过”的不同高度通道。

## 三份配置

| 配置 | XY 范围 / 栅格 | 高度范围 | 用途 |
|---|---|---|---|
| `ego_2d_planner.yaml` | 10×10 m / 200×200 | 世界 z=0.1～2.0 m | 默认，保持原障碍输入范围 |
| `ego_2d_static_local.yaml` | 8×8 m / 160×160 | 世界 z=0.1～2.0 m | 小范围试验，目标需在局部地图内 |
| `ego_2d_static_slice.yaml` | 8×8 m / 160×160 | 固定规划高度上下各 0.3 m | 离线高度层候选；当前 fixed_z=1.0，对应 z=0.7～1.3 m |

三份配置均保留 0.05 m 分辨率、0.45 m 膨胀和永久障碍缓存。小地图会改变边界和可搜索路径；窄层会改变障碍信息，不能称为与原配置严格等价。请不要把 `cloud_2d` 再接回本节点输入，否则会重复量化且失去原高度信息。

## 编译与运行

将本包放入 ROS 2 Humble 工作空间的 `src/`，确保原有 `quadrotor_msgs` 依赖已经安装或位于同一工作空间。

```bash
source /opt/ros/humble/setup.bash
cd ~/ros2_ws
colcon build --packages-up-to ego_2d_planner_pkg --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
ros2 launch ego_2d_planner_pkg ego_2d_planner.launch.xml
```

选择小地图配置：

```bash
ros2 launch ego_2d_planner_pkg ego_2d_planner.launch.xml \
  config:="$(ros2 pkg prefix ego_2d_planner_pkg)/share/ego_2d_planner_pkg/config/ego_2d_static_local.yaml"
```

离线回放时两个终端均设置同一个独立 ROS 域，使用仿真时间；以下不启动轨迹服务器：

```bash
export ROS_DOMAIN_ID=187 ROS_LOCALHOST_ONLY=1
ros2 launch ego_2d_planner_pkg ego_2d_planner.launch.xml \
  use_sim_time:=true use_traj_server:=false
```

```bash
export ROS_DOMAIN_ID=187 ROS_LOCALHOST_ONLY=1
ros2 bag play /path/to/rosbag2_2026_10_02-19_36_01 --clock 100
```

RViz Fixed Frame 设为本 bag 的 `lidar`，添加 PointCloud2 `/ego_2d_planner/cloud_2d` 查看投影层。性能测试没有启动 RViz，也没有二维点云订阅者；打开可视化会有额外开销。

## 验证结果与解释

测试平台为 WSL Ubuntu 22.04 / ROS 2 Humble / x86-64 / Release，并非 Jetson Orin NX。完整 bag 为 106.50 s，包含 1065 帧点云、1065 条里程计及 6 个目标，平均约 1248 点/帧。

| 原配置，完整 1 倍速 ROS 回放 | 原版 | 优化版 |
|---|---:|---:|
| 规划器进程平均 CPU，单核 100% 口径 | 6.63% | 3.57% |
| 1 秒采样窗口 CPU 峰值 | 9.98% | 4.99% |
| 进程峰值 RSS | 26000 KiB | 26200 KiB |
| 核心计算 CPU 总时间，三轮中位数 | 4338.26 ms | 521.88 ms |

ROS 回放各一轮，平均 CPU 下降约 46%，1 秒峰值下降约 50%；核心计算三轮下降约 88%。内存没有观察到明显下降。核心计时不包含 ROS/DDS、日志和可视化，不能与进程 CPU 百分比混用，也不能据此预测 Orin 上的 80% 会降到多少。

1065 帧逐帧对比：占用图完全一致，42,600,000 个距离值最大绝对误差 2.22e-15 m；93 次独立规划状态一致，原始 A* 路径完全一致，输出轨迹点最大差异 9.93e-16 m，控制点最大差异 8.88e-16 m，时长一致。两版均为 72 次成功、21 次失败，失败也被保留在比较中。数值差异来自浮点加法顺序，不承诺所有场景逐位相同。

另通过 612 组距离场 oracle 检查、180 帧 / 4320 次 A* 地图回归和 38 项 ROS 高度层/空云/异常字段检查。ROS 定时器回放规划次数存在轻微调度差异（52/53 条成功日志），不能用日志次数证明轨迹等价；上面的确定性核心对比负责验证结果。

bag 的原始飞行轨迹不作为最佳路线。它只提供观测历史与起点；比较的是两版算法从相同输入重新算出的路径。回放无法模拟新路线会看到哪些新障碍，未完成闭环仿真或实机飞行，也没有证明路径最优。

8×8 m 配置把栅格数减少 36%；仅原始占用、膨胀占用和距离三个数组由约 391 KiB 减到 250 KiB，并不是整个节点内存减少 36%。永久障碍缓存仍随探索范围增长，本次 bag 最多 1602 个永久格，不能代表长时间运行。为保留原来的历史障碍语义，本次没有自动淘汰永久缓存。

8×8 m 全高度配置的一轮 ROS 回放测得平均 CPU 3.25%、1 秒峰值 4.96%、峰值 RSS 25712 KiB。它与原配置的独立核心规划均为 72/93 次成功，但其中一帧失败原因由路径太短变为控制点不足，不能用相同成功数量宣称输出等价。8×8 m 窄层候选也完成了完整核心回放，未做完整 ROS 性能回放和闭环验证。

## 原有问题，本次未改变

1. `EMERGENCY_STOP` 只发布 local_goal，而轨迹服务器执行 Bspline2D，没有相应撤销旧轨迹。这是原有停止链路缺陷，资源优化没有修复它。
2. 速度/加速度主要作为软惩罚，不能保证严格限幅；重规划起点时间与发布执行时间也有偏差，不能保证实际指令连续。
3. 碰撞检测是离散采样，仍可能漏过栅格角点附近的短穿越；未增加连续扫掠碰撞验证。
4. 原逻辑假设点云、里程计、目标已经处于同一个固定坐标系，没有 TF 转换及完善的输入过期处理。frame 名相同本身不证明坐标语义正确。
5. 永久障碍不清除。即使场景静态，误检和定位漂移也会形成残留障碍，并让缓存随探索范围增长。

完整结果、日志和 C++ 复现工具在交付工作目录的 `analysis/` 与 `tools/`；这些测试结论不替代上述原有问题的修复。
